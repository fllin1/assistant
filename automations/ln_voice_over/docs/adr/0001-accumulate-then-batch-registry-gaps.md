# Accumulate-then-batch registry-gap workflow with hard validation at the `reviewed/` boundary

When **Narrator detection** or **Speaker** attribution produces a name the **Character registry** cannot resolve, the pipeline does **not** pause: it writes the LLM-raw name as a placeholder into the intermediate stage (`manifest.json` `narrator` field for detection; per-chunk JSONs under `extracted/` for speakers) and logs the unresolved name as a **Registry gap**. A dedicated resolution step processes the accumulated gap log — model proposes, human confirms, registry updates — *before* canonical data is written. The boundary into `reviewed/` is hard-validated: REVIEW refuses to write a `reviewed/chapter_NN.json` while any gap is still open for that **Chapter**.

We chose this over **pause-on-gap** (block parallel attribution at the first unresolved name) because attribution runs up to 8 Sonnet sub-agents in parallel over ~80-segment chunks; pausing each agent on first encounter would serialise the run and force the human to context-switch repeatedly. The cost — placeholders in intermediate files — is contained: the hard-check at `reviewed/` keeps the canonical data clean and surfaces missing gap-closures loudly, not silently at synthesis time.

The same rule applies uniformly to detection and attribution; there is no special case for the chapter's `narrator` field. This is the load-bearing reason `extracted/` content can disagree with the registry while `reviewed/` cannot — a future reader looking at the file formats would otherwise wonder why the contracts differ.
